# Front-End Developer Interview Preparation

## 1. Tell me about a front-end application you delivered.

At NASA / ORNL DAAC, I repurposed NASA's Cumulus Dashboard to power Earthdata Pub Overview and Forms applications built with Vue and React. They support all 12 NASA DAACs and their Data Producers. I was involved not only in the interface, but also in the surrounding architecture, API integration, and ongoing modernization, which helps me make UI decisions with the whole application in mind.

## 2. What does accessibility-minded development mean in your day-to-day work?

I treat accessibility as part of building a usable interface, not as a separate add-on. That means using semantic HTML, ensuring keyboard access and visible focus, providing clear labels and meaningful feedback, respecting reduced-motion needs, and checking that information is not conveyed by color alone. I build those decisions in as I work rather than leaving them for the end.

## 3. How do you work with React and Vue?

I have hands-on experience delivering applications with both Vue and React. I focus on component boundaries that reflect user tasks, predictable data flow, and interfaces that remain understandable as requirements change. My experience with APIs and backend systems also helps me work effectively across the front-end/backend boundary.

## 4. How do you turn stakeholder feedback into an interface?

I start by learning what the user is trying to accomplish, what decisions they need to make, and what information or failure states can block them. I have worked directly with research stakeholders, doctors, agency users, and publishing teams. I translate that input into clear workflows, validate assumptions early, and use documentation or demonstrations to keep feedback concrete.

## 5. How do you protect quality in front-end changes?

I use automated unit and end-to-end testing for important user paths, and I pair that with practical manual checks for interactions, responsiveness, and accessibility. At NASA / ORNL DAAC, adding automated tests improved deployment confidence and reduced regression defects. I see testing as a way to make future changes safer, not just as a release gate.

## Questions to ask the interviewer

- Which user journeys are most important to the product today?
- How does the team include accessibility and usability in its definition of done?
- How are design, front-end, API, and QA responsibilities shared?
